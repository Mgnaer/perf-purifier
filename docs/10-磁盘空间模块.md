# 模块 C：磁盘空间（C 盘瘦身）设计说明

> 版本：1.2.0 ｜ 安全边界：默认只读；执行层默认关闭；删除只进回收站；不联网、不自动提权。

## 1. 目标与定位

在既有「性能与净化」框架中新增第六个页签与一组 CLI 命令，回答两个问题：

1. **空间去哪了**：分区用量、卷根顶层目录占用、最大文件（一次遍历全出）；
2. **能安全清掉什么**：按声明式规则扫描临时文件/应用缓存/更新包残留/系统缓存，
   经预演与二次确认后移入回收站。

它不替代「临时占用页」（模块 A）：模块 A 关注当前用户临时目录的**文件级**占用探测；
模块 C 关注**全盘空间构成**与**可清理规则库**（目录级、可含系统级路径、需要管理员时标注）。

## 2. 分层架构

```
module_c/
├─ models.py      JunkRule / JunkItem / JunkRuleResult / SpaceScanResult / DriveInfo …
├─ safety.py      路径归一、受保护路径段、用户数据区、重解析点、身份重验、Defender 判定、
│                 回收站查询/清空（ctypes shell32）
├─ rules.py       34 条声明式规则 + 根模板解析（%ENV% / 末段 *）+ 规则库自检
├─ scanner.py     只读遍历：walk_size / list_children / largest_files / overview_scan / 分区
├─ scan.py        扫描编排：scan_rule / scan_junk_rules / dedupe / scan_space（含完整度判定）
├─ policy.py      SlimTarget + evaluate_slim_targets + build_slim_preview（批量闸门 + 逐项）
├─ executor.py    SlimDeleteExecutor（回收站后端 + 专用通道）
├─ report.py      垃圾明细 CSV / 顶层占用 CSV / 完整 JSON
└─ win_trash.py   回收站查询与清空（shell32）
```

GUI 集成：`ui/pages/page_space.py`（页面）、`ui/models/space_models.py`（三个表格模型）、
`jobs/space_job.py`（QThread 扫描任务）。
CLI 集成：`src/perf_purifier/cli.py`（overview/scan/clean/large/history/rules/config/menu）。

## 3. 数据流

```
scan_space()
  ├─ scanner.drive_usage()                 分区总量/可用
  ├─ scanner.overview_scan()               单遍：顶层子项聚合 + 最大文件 Top N
  ├─ rules.select_rules(caution, system)   按用户勾选挑规则
  ├─ scan.scan_junk_rules()                逐规则只读扫描 → JunkRuleResult[]
  └─ dedupe + compute_completeness()       跨规则物理路径去重 + full/partial/limited 判定

clean
  ├─ build_slim_preview(items)             evaluate_batch_gate + 逐项判定 + 预览 token
  ├─ （GUI）首次预演闸门 → ConfirmActionDialog → ActionJob(executor=SlimDeleteExecutor)
  ├─ （CLI）y/N 确认 → 逐项 executor + 直接写 operations.jsonl
  └─ executor: check_deletable() → core.trash.Send2TrashBackend → 审计结果
```

## 4. 规则库（34 条）

等级含义：**安全** = 默认清理（删了自动重建/可重下）；**谨慎** = 需 `--caution`/勾选
（游戏缓存、缩略图、驱动备份）；**系统** = 需管理员（Windows 自身缓存/日志/转储）。

| 类别 | 规则 id | 等级 | 说明 |
|---|---|---|---|
| 临时文件 | `temp_user` | 安全 | `%TEMP%`/`%TMP%`/`%LOCALAPPDATA%\Temp` 内容 |
| 临时文件 | `temp_shared` | 谨慎 | `ProgramData\boost_interprocess`（多被占用） |
| 临时文件 | `inetcache`、`pip_cache` | 安全 | IE/系统网络缓存、pip 下载缓存 |
| 更新残留 | `updater_caches` | 安全 | `%LOCALAPPDATA%\*-updater` 整个目录 |
| 更新残留 | `epic_update_cache`、`office_solution_packages` | 安全 | 启动器/Office 更新缓存 |
| 更新残留 | `vendor_driver_archives` | 谨慎 | `C:\DrvPath`、`C:\KDubaSoftDownloads` |
| 更新残留 | `win_update_cache`、`win_lcu_cache`、`win_setup_temp`、`win_mrt` | 系统 | Windows 更新/LCU/SET*.tmp/MRT.exe |
| 浏览器 | `edge_cache`、`chrome_cache`、`firefox_cache`、`b360_browser_cache` | 安全 | 只清 Cache/Code Cache/GPUCache/CacheStorage |
| 浏览器 | `electron_app_caches` | 安全 | B站/抖音/网易/雷神/QQ 客户端缓存 |
| 游戏缓存 | `game_hogwarts_shaders`、`game_forza_scratch`、`game_bf5_shaders` | 谨慎 | 着色器/图形缓存（会重建） |
| 游戏缓存 | `gpu_shader_caches`、`game_uagame_cdn` | 谨慎/安全 | 显卡着色器缓存（部分被驱动锁定）、UAGame CDN |
| 启动器 | `steam_htmlcache`、`ea_ac_cache` | 安全 | Steam 网页缓存、EA 反作弊缓存 |
| 崩溃日志 | `user_crash_dumps`、`user_wer_reports` | 安全 | 用户崩溃转储/错误报告 |
| 崩溃日志 | `machine_wer_reports`、`win_minidump`、`win_cbs_logs`、`win_panther`、`win_temp` | 系统 | 系统错误报告/转储/组件日志/安装日志/Temp |
| 缩略图 | `thumbnails` | 谨慎 | `thumbcache_*.db` / `iconcache_*.db` |
| 系统组件 | `defender_old_platforms` | 系统 | Defender 旧平台版本（保留最新，专用通道） |
| 回收站 | `recycle_bin` | 谨慎 | 清空回收站（专用通道 + 输入确认词） |

规则约束（`rules.validate_rules()`，测试断言为空）：
- 根目录不得是卷根、不得命中受保护路径段、不得位于用户数据区；
- Windows 下的根必须来自 `SYSTEM_ROOT_ALLOWLIST`（如 `C:\Windows\Temp`）；
- `files` 模式必须声明 `file_globs`；专用通道（回收站/Defender）豁免根目录检查但仍受限。

## 5. 安全不变量

| 闸门 | 位置 | 内容 |
|---|---|---|
| ① 规则准入 | `rules.validate_rules` | 见上；防止误加危险规则 |
| ② 批次闸门 | `core.action_policy.evaluate_batch_gate` | `stage2_enabled` + `allow_clean_space` 双开关；`verdict.limited` 禁止批量；单次 ≤ 500 项 / 10 GiB |
| ③ 逐项判定 | `module_c.policy.evaluate_slim_targets` | 路径为空/重复/不存在/越界/根不可信/重解析点/未知通道/需管理员/受保护路径/用户数据 → 逐项拒绝（不静默） |
| ④ 执行前重验 | `module_c.executor` → `safety.check_deletable` | 再次检查存在性、根归属、受保护序列、用户数据区、重解析点、文件大小/mtime 一致性 |
| ⑤ 后端语义 | `core.trash.Send2TrashBackend` | 只进回收站；失败仅报告；**绝不**回退永久删除 |
| ⑥ 审计 | `core.audit.ActionAuditWriter` | 先写 header 再执行，逐项 item，结束 end；写失败即中止 |

补充：
- **目录可删但逐项校验**：`children/tree` 模式允许删除目录，但目录必须位于规则根内，
  且不跟随任何重解析点；
- **专用通道**：回收站清空与 Defender 旧平台不走通用路径删除（后者先判定"非最新、
  非 CurrentVersion 链接"）；
- **跨规则去重**：同一物理路径（含 8.3 短名/长名）只计划一次；
- **完整度**：扫描预算触顶/无数据/不可读比例过高 → `limited` → 禁止批量动作。

## 6. GUI 交互（第六页签「磁盘空间」）

1. 顶部：盘符选择、包含谨慎级/系统级（系统级需管理员）、大文件阈值、「开始扫描」、
   导出垃圾 CSV / 完整 JSON；
2. 概览区：磁盘占用条 + 顶层目录表（名称/类型/占用/占已用/文件数，双击打开目录）；
3. 垃圾规则区：规则聚合表（勾选/类别/规则/等级/项数/大小/说明），
   按钮「全选安全级 / 全选可清理 / 清空选择 / 预演选中项 / 清理选中项 / 清空回收站」；
4. 大文件区：Top N 表 + 打开所在目录；
5. 执行层默认关闭：清理按钮禁用并在提示中给出 `config.json` 开关名；
   开启后仍需「首次预演 + 勾选 + 二次确认」，执行结果与失败明细弹窗展示，
   全部写入审计日志。

## 7. CLI

`perfpurifier-cli`（或 `python run_cli.py`）复用同一套 engine：

- `overview` / `scan` / `clean` / `large` / `history` / `rules` / `config` / `menu`；
- `clean` 默认预演，`--apply` 才执行；`--yes` 跳过确认；`--empty-trash` 立即释放空间；
- 支持 `--caution` / `--system` / `--only` / `--skip` / `--exclude` / `--json`；
- 退出码 0/2/130；控制台自动 UTF-8 + ANSI 颜色，重定向时自动纯文本。

## 9. 已知限制与后续

- 用户级规则只覆盖当前用户；其他账号的临时目录需要管理员并另行实现；
- 部分目录被系统/显卡驱动锁定（如 AMD 着色器缓存），每次能清掉的比例不固定；
- 回收站容量超限时删除会失败并提示（可清空回收站后重试），不会退化为永久删除；
- 后续可扩展：目录联接迁移（搬大目录到其他盘）、重复文件页面联动清理、
  按应用归因的缓存报表。

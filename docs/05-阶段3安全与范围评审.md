## 4. 关键安全设计

- **dry-run 保真**：预演只注入 `DryRunExecutor`，禁止复用真实 executor；审计 `dry_run=true`；
  测试断言预演后文件内容/硬链接/进程/回收站调用均无变化。
- **首次预演闸门**：`core.first_run` 记录三个动作各自的标记；真实执行前若未预演 → 提示并中止；
  预演完成后写 config.json；设置页可重置标记。
- **设置页摩擦（S3-3）**：只能关闭不能开启；关闭立即写盘并生效；开启必须手工编辑 config.json
  后重启；配置损坏时 `AppConfig.load` 默认全关。
- **审计轮转（S3-7）**：只在动作会话结束后（finished/failed/cancelled）按大小轮转，
  重命名 `operations-YYYYmmdd-HHMMSS.jsonl`，保留 10 份/30 天；轮转失败静默不影响主流程。
- **历史查看器（3B 设计约束）**：只读、字节上限分页、`errors="replace"`、坏行跳过计���；
  不执行日志内容、不提供导出/重做/撤销。
- **管理员重启（3C 设计约束）**：目标必须是 `sys.executable` 自身路径；仅一次 UAC 调用；
  失败留在当前进程并提示；不记录密码、不绕过 UAC；测试 mock `ShellExecuteW`。

## 5. 测试与验收策略

- 预演零副作用：对比文件内容/硬链接 inode/进程/回收站调用记录；
- 首次预演闸门：未预演时真实执行被阻止且不产生审计与动作；
- 设置页：关闭写盘生效、开启无入口、config 损坏降级全关；
- 审计轮转：大小阈值、唯一命名、keep/期限裁剪、IO 失败静默；
- 3B/3C：历史解析异常输入、管理员重启 mock 参数与失败分支；
- 每个里程碑保持全量测试全绿，并给出对应手工验收步骤。

### 3A 手工验收步骤

1. 默认配置下三个动作页"预演选中项"在勾选后可用，真实动作按钮不可用；
2. 设置页显示四个执行层开关为"关闭"，点"一键关闭"无副作用（已关闭状态）；
3. 手工开启开关后重启，直接点真实执行 → 提示"首次使用请先预演"；
4. 点"预演选中项（不执行）" → 弹出预演结果，文件/进程/硬链接均未改变；
   审计日志 `operations.jsonl` 出现 `dry_run=true` 的 header + item；
5. 再次点真实执行 → 进入二次确认（取消无动作）；
6. 设置页"一键关闭所有执行层开关" → 立即生效、三个动作按钮变灰、config.json 写入 false；
7. 设置页"重置首次预演标记" → 下次真实执行前需重新预演；
8. 多次动作使 `operations.jsonl` 超过 10MB 后，会在会话结束时轮转为 `operations-*.jsonl`
   （保留最近 10 份、删除超过 30 天的轮转文件）。

1. 先执行过至少一次动作（或按 docs/03 §5 手工验收产生记录），再打开"动作历史"页；
2. 应显示日志目录、读取文件数/字节数、记录数、会话数、跳过坏行数（含"只读"标识）；
3. 用"动作/结果"下拉与搜索框筛选，列表与摘要中的"当前筛选 N 条"一致；
4. 选中一条记录，右侧显示原始 JSON 字段（只读）；不出现删除/执行/结束/撤销等按钮；
5. 手工向 `operations.jsonl` 追加一行 `not-json` 再刷新 → 记录仍可显示，坏行计数 +1，不崩溃；
6. 用记事本确认 `operations.jsonl` 未被程序改写。

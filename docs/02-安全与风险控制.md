# 安全与风险控制（阶段 1A 已生效，阶段 2 复用）

## 1. 两道互相独立的名单

| 名单 | 位置 | 作用 | 当前状态 |
|---|---|---|---|
| **分析白名单** | `core/whitelist.py → Whitelist` | 抑制启发式误报：受信路径（SystemRoot/System32/Program Files/ProgramData…）、用户自定义路径/进程名 | ✅ 已生效 |
| **动作黑名单** | `core/whitelist.py → NEVER_TERMINATE_NAMES / PROTECTED_PATH_MARKERS` | 阶段 2 处置动作**永不触碰**的进程与路径 | ✅ 已定义 + 单测锁定，尚无调用方 |

分析白名单只影响"显示哪些标记"，**绝不作为放行处置的依据**；阶段 2 的每个动作都必须
重新做路径规范化与动作黑名单校验。

## 2. 路径匹配纪律

- 统一 `normalize_path()`：`abspath + normcase + 去尾分隔符`；
- 前缀匹配按**目录边界**（`== root` 或 `startswith(root + os.sep)`），
  杜绝 `C:\Program FilesEvil` 这类前缀骗术；
- 兜底实现为 `os.path.normpath` + `normcase`，展示仍保留原始路径字符串。

## 3. 阶段 2 动作闸门（设计定稿，代码未实现）

```
用户勾选目标 → 生成预览清单（路径/mtime/大小/hash 快照 token）
            → 二次确认（逐项展示 + 汇总）
            → 执行前校验：路径归一化、动作黑名单、清单 token 是否仍匹配
            → 逐项执行（失败不中断）
            → 每项写 operations.jsonl（时间/动作/目标/结果/错误码）
```

- 结束进程：拒绝 PID 0/4、`NEVER_TERMINATE_NAMES`、本程序自身及祖先链；非预期路径的
  同名系统进程只允许"标记"不允许自动处置；
- 删除文件：**只允许 `send2trash`**；失败时保留文件并报告，**禁止回退为永久删除**；
  回收站不可用（网络盘/配额）必须提前警示；
- 硬链接：仅同卷 NTFS、仅内容完全相同的重复组、默认关闭、UI 明示
  "两个路径指向同一份数据，修改一个会影响另一个"；跨盘降级为"保留副本 / 删除"。

## 4. 风险清单与缓解（当前版本）

| 风险 | 影响 | 当前措施 |
|---|---|---|
| 误报被当成结论 | 用户误判/误删 | 只输出"规则命中 + 证据"；界面/文档明确"不是杀毒软件"；等级仅用于排序 |
| 结束系统进程 | 蓝屏/丢数据 | 阶段 1 无结束按钮；阶段 2 黑名单 + 二次确认 |
| 误删用户文件 | 数据丢失 | 阶段 1 无删除按钮；默认不勾选、预览、回收站、日志（阶段 2） |
| 命令行泄漏口令 | 隐私泄露 | 导出/界面默认脱敏（`-p/--token/-enc 载荷` 等），可配置关闭 |
| 签名校验卡顿/联网 | UI 卡住/产生网络流量 | `WTD_CACHE_ONLY_URL_RETRIEVAL` 禁止在线吊销；只校验非受信路径 exe；250 文件/8s 预算；结果缓存 |
| 系统文件被误报“无签名” | 大面积误报 | 受信路径一律 `CATALOG_OR_UNKNOWN`，不做“无签名”结论 |
| 占用探测干扰业务 | 误判/短暂句柄 | 只读 `CreateFileW(share=0)`、立即关闭、只探测最大若干个 ≥1MB 文件、2s 预算；未探测明确标注 |
| PID 0 连接归因错误 | 误报“System Idle Process 外联” | 显式 `is_kernel` 标记，不归因进程、不计入“需人工核实” |
| HTML 报告注入 | 恶意文件名污染报告 | 所有动态内容 `html.escape`，报告无 `<script>`/外链，单测锁定 |
| 重复扫描误判 | 误把不同文件当重复 | 4KB 指纹仅预筛，最终以全文件 SHA-256 为准；读取前后 stat 校验稳定性，变动文件剔除 |
| 硬链接误判 | 高估可回收空间/误导删除 | 去重阶段用 `os.stat` 补全 (卷, inode)；全组同 inode 标"删除无收益"；inode 不可读时保守估算并警告 |
| 遍历进入 junction/云盘 | 越界扫描/触发下载 | REPARSE 位不跟随；云占位属性跳过；系统目录白名单；深度/文件数/时间预算 |
| 大目录扫描长时间占用磁盘 | 影响正常使用 | 单线程顺序读取、随时取消、遍历 30 万文件/120s 预算；阶段 2 再评估低优先级 I/O |
| junction/符号链接 | 越界扫描 | 1B/1C 用 `GetFileAttributesW & FILE_ATTRIBUTE_REPARSE_POINT` 判定，不依赖 `os.path.islink` 版本差异 |
| 云占位文件 | 触发下载 | 1C 检测 `OFFLINE / RECALL_ON_*` 属性直接跳过 |
| 权限不足 | 数据缺失 | 逐字段降级 + 完整度徽标 + 横幅提示，不中断、不崩溃 |
| PID 复用 | 血缘错误 | `create_time` 交叉验证 + 进程对象 `is_running()` 身份校验 |
| 大目录/大进程数 | UI 卡顿 | 异步线程 + 上限 4000 进程 + 10Hz 进度合流 + 取消令牌 |
| 导出注入 | HTML 报告可被文件名污染 | 1B HTML 统一 `html.escape`，不引外部资源 |
| 崩溃丢现场 | 无法定位 | 全局 excepthook + 轮转日志 + 会话级异常上报 UI |

## 5. 明确不做

- 不自动提权、不绕过 UAC、不注入、不加载驱动、不联网;
- 不做"一键清理内存"、不承诺加速效果；
- 不默认全选、不默认执行任何处置动作；
- 不在用户未确认的情况下写入注册表/启动项。
